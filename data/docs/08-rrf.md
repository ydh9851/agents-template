# RRF 倒数排名融合

RRF（Reciprocal Rank Fusion）是混合检索里最常用的结果融合算法，本框架用它把 BM25 和向量检索的结果合成一个排序。

## 公式

```
score(d) = Σ  1 / (k + rank_i(d))
        i∈各路检索
```

其中 `rank_i(d)` 是文档 d 在第 i 路结果里的名次（从 1 开始计），`k` 是平滑常数，默认取 60。

## 为什么用 RRF 而不是加权分数

BM25 的分数是无上界的实数（可能 0.3，也可能 25），余弦相似度固定在 [-1, 1]。直接线性加权需要先做归一化，而归一化方式的选择会显著影响最终排序，很难调。

RRF 只用名次、不用分数，天然免疫量纲问题，而且实现只有十几行。

## k 的作用

`RRF_K` 越小，头部名次之间的区分度越大（第 1 名和第 2 名差距明显）；越大则越平滑，各路结果的权重越均匀。实践上 60 是比较通用的取值，本框架也默认 60。

## 实现细节

1. 两路各召回 `max(top_k * 3, 10)` 条候选，给融合留出空间；
2. 用 `rrf_fuse` 计算融合分并降序排列；
3. 取前 `RAG_TOP_K`（默认 3）条，附带来源文件名与融合分返回给 Worker；
4. 如果同一文档被两路同时召回，分数会叠加，等效于拿到了「双路认可」的加成。

## 调试建议

调 `POST /retrieve` 接口可以单独观察混合检索的结果。如果发现某路明显不work，先把 `RAG_TOP_K` 调大到 5 看召回情况，再决定是改切分粒度还是换 embedding。
